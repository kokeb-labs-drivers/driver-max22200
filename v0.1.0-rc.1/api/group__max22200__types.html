◆ Error

enum class max22200::Error : uint8_t
strong

Why a call failed. Every call of the driver returns one of these in its Result.

Values 0 to 9 are the shared base set; chip-specific values start at 16. The type is [[nodiscard]]: a call that returns a bare Error and is used as a statement is a warning (handbook KB-CPP20-037).

Enumerator
Ok 

The call succeeded.

NotInitialized 

EnsureInitialized() has not succeeded, Deinitialize() ran since, or a call found the chip reset (DeviceReset).

InvalidArgument 

An argument or a Config field is out of range; nothing was sent.

Bus 

The port's Transfer() (or EnsureInitialized()) returned false.

Timeout 

At start-up, ACTIVE did not read 1 within Config::wake_timeout_us with UVM clear (Figure 6, "wake-up completed?"). If it persists, cycle VM: ENABLE low is not a reset (p14, p22).

DeviceIdMismatch 

At start-up, STATUS read back differs from what was written, or the command echo of a 32-bit write is wrong: not a MAX22200 answering, or SDO or SDI broken.

Crc 

Not returned by this driver (the chip sends no CRC).

Busy 

Not returned by this driver (the chip is never busy to SPI).

DeviceFault 

Not returned by this driver: faults are data (ReadStatus(), ReadFaults()), never a failed call.

Unsupported 

The port lacks the optional hook (ReadFaultPin()), or a selective fault clear asked of a MAX22200 (only the MAX22200A has it).

NoDevice 

At start-up, STATUS read as 0xFFFFFFFF with a 0xFF fault byte: nothing drives SDO (no chip, no supply, ENABLE not reaching it).

Pin 

The port's GpioSet() could not drive CMD or ENABLE. A CMD that cannot go high would turn the command into data: nothing was sent.

CommunicationError 

COMER: the chip counted the wrong number of clocks in a write and ignored it. At start-up after kStartAttempts tries (Figure 6), each after ENABLE low and high: if it persists, cycle VM. On a running driver: the first call that sees COMER go from 0 to 1 (the write may have been an earlier call's), or a read-back that differs with COMER set.

WriteMismatch 

A register read back differs from what was written: at start-up, or with Verify::ReadBack. The chip did not take the write (a frame lost on a shared bus, a channel still on, a TRIG pin high).

Undervoltage 

At start-up, UVM was still set at Config::wake_timeout_us (the chip needs UVM cleared to enable operations, p27). VM is low, rises slowly, or UVM is stuck: the driver stays uninitialised, so retry later or treat it as a warning; a VM power cycle clears a stuck UVM.

ChannelsActive 

A setting the chip takes only with the channels off (VDRnCDR, HSnLS: every channel; CMxy: both of the pair) asked while one is on. Nothing was sent.

DeviceReset 

Any call of a running driver saw ACTIVE = 0 in a fault byte or in STATUS: a power-on reset cleared every register. Nothing more was sent to the chip; the driver is uninitialised; call EnsureInitialized() to configure the chip again.

Uncertain 

The call depends on a setting a failed write left unknown (the reply failed, so the chip may hold the old or the new value): a pair mode for a switch-on in that pair (a switch-off is never refused). Nothing was sent. Write the setting again (SetPairMode(), ApplyConfig()) or read it back with Verify::ReadBack, or switch the pair off with SetChannelsOn().

◆ Variant

enum class max22200::Variant : uint8_t
strong

Which part is fitted. The chip cannot tell, so it is configured: the two differ only in how a FAULT read clears the flags ("Clearing the FAULT Register", Ordering Information).

Max22200, the default, is correct on both parts: ClearFaults() clears every flag on either, and a selective clear is refused; the two parts cannot be told apart over SPI. Choose Max22200A only when the bill of materials says the MAX22200A is fitted and a bench check shows a zero-SDI read keeps a latched flag: a selective clear sent to a MAX22200 clears every flag.

Enumerator
Max22200A 

Selective clear on read: only the flags whose SDI bit is high clear.

Max22200 

Every FAULT read clears every flag, whatever SDI carries. The default.

◆ Verify

enum class max22200::Verify : uint8_t
strong

Extra verification for one call, chosen per call (handbook KB-ARCH-041).

The datasheet needs none of it: Verify::None, the default, sends only the transfers the chip needs. Verify::ReadBack reads the register back, compares it and checks the COMER flag of the read's fault byte; each call that takes it says how many transfers it adds.

Enumerator
None 

No extra transfer and no compare. The default.

ReadBack 

Read the register back and compare it; check COMER.

◆ kDefaultWakeTimeoutUs

constexpr uint32_t max22200::kDefaultWakeTimeoutUs = 100000
inlineconstexpr

Config::wake_timeout_us by default: 100 ms. tWU is 2.5 ms at most once ACTIVE is taken, but UVM clears only once VM is above UVLO (p22), so the wake also waits for the supply ramp; the default allows a rail that settles within tens of milliseconds. Raise it for a slow supply.
