Detailed Description

template<SpiPort Port>
class max22200::MAX22200< Port >

Driver for one MAX22200 or MAX22200A on a platform port.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start (ENABLE, tEN, the programming procedure of Figure 6, tWU, read-back of every register), use, optionally Deinitialize(). Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded; no call starts the chip as a side effect.

The driver keeps a copy of what it wrote (STATUS, the eight CFG_CHn, CFG_DPM), so switching channels is one 8-bit write and never a read-modify-write: SetChannel() costs what SetChannelsOn() costs. An access is two transfers: the command byte with CMD high, then the data with CMD low. The command stays in force until it is rewritten (p25), so an ONCH write right after another ONCH write sends only its data byte: the hot path is one transfer.

A hook declared with the wrong signature (for example void GpioRead(...), or DelayUs(uint16_t)) is a compile error. DelayUs(uint32_t) noexcept is required.

What every call of a running driver checks, at no extra I/O. Every command byte clocks out the fault byte STATUS[7:0] (Figure 7), and so does an 8-bit write's data byte (Figure 12):

  • A power-on reset. ACTIVE is only ever written 1 while running, so a fault byte with ACTIVE = 0 (other than 0xFF, what a floating SDO reads) means a UVLO reset every register ("Undervoltage Lockout (UVLO)", p22). The access stops before its data phase, so nothing from the driver's copy reaches the reset chip; the driver marks itself uninitialised, every channel off, and the call returns DeviceReset. Call EnsureInitialized() again. A STATUS read whose value shows ACTIVE = 0 does the same. An SDO stuck low reads the same way: the driver stops, which is the safe side.
  • A miscounted write. COMER going from 0 to 1 (p34) means a write since the last fault byte with COMER clear was ignored. The call that sees it returns CommunicationError (once); the ONCH bits those writes changed count as on for the ChannelsActive check, the channels they configured as of either mode, and ApplyConfig() writes their registers again. COMER is read only and may stay set (p36), which would hide every later miscount: the start-up clears a COMER the wake left with ENABLE low, and while COMER is set on a running driver every switch-off is read back (2 more transfers each, only in that state), so a switch-off is never reported Ok without proof that it landed. A configuration write whose command byte shows a new COMER stops before its data phase (CommunicationError): what it checked first, every channel off for a mode change say, may no longer hold. An ONCH write is never stopped.
  • An off request is never refused. In a pair whose mode is in doubt, switching a channel off (SetChannel(ch, false), SetBridge(pair, BridgeState::HiZ), or a SetChannelsOn() mask that clears any bit of the pair) switches both channels of the pair off: ONCHx = ONCHy = 0 is off in every mode (Tables 6 and 7), and one bit alone could turn a full-bridge Brake into Forward or Reverse. The partner channel goes off too. A switch-on in such a pair returns Uncertain; in a SetChannelsOn() mask that pair is switched off instead, and the rest of the mask, every switch-off in it, still goes out. SetChannel(ch, false) in a known full-bridge pair sets HiZ, the partner off too. IsMiscountDetectionDegraded() says when COMER cannot show a new miscount.
  • All-ones read data. It carries no fault byte, and a chip reset between a read's command byte and its data forgets the command and leaves SDO floating: the driver then sends one more command byte (an 8-bit ONCH read, 2 transfers) to tell a reset from a value.
  • Flags the chip clears by itself. OVT, UVM, OCP, OLF, HHF and DPM in every fault byte go into GetLatchedFaults(), so an OLF a switch-on clears (p21) or an HHF a new cycle clears (p23) is kept even though no FAULT read saw it.

◆ Deinitialize()

template<SpiPort Port>
Result< void > max22200::MAX22200< Port >::Deinitialize ( )
noexcept

Switch every channel off and the chip to sleep, and mark the driver uninitialised: one STATUS write with every ONCH 0 and ACTIVE = 0 (channels Hi-Z), then ENABLE low. The outputs are Hi-Z at the latest tDIS after ENABLE falls; the call does not wait for it.

ENABLE is driven low even if the write failed, and the driver is uninitialised afterwards whatever happened; the next EnsureInitialized() configures the chip again. On an uninitialised driver it does nothing and returns Ok.

Returns
Ok, Bus or Pin (the first failure).

◆ EnsureInitialized()

template<SpiPort Port>
Result< void > max22200::MAX22200< Port >::EnsureInitialized ( )
noexcept

Start the chip, once: the only way to initialise the driver.

In order: Validate() the configuration (no I/O); bring the bus up; CMD high (its idle level), ENABLE high and tEN; then the programming procedure of Figure 6: read STATUS (clears UVM); wake the chip ("wake-up completed?"): a bare ACTIVE = 1 write, tWU, a STATUS read, repeated every kWakePollUs until ACTIVE reads 1 with UVM clear, for at most Config::wake_timeout_us; then write STATUS (masks, FREQM, pair modes, every channel off, ACTIVE = 1), CFG_CH0 to CFG_CH7 and CFG_DPM. Then the start-up checks: STATUS must hold what was written, and every 32-bit write must have echoed its command (Figure 10). Next FAULT is read and every flag cleared: the chip keeps its registers until a power-on reset ("Undervoltage Lockout (UVLO)", p22) and ENABLE low is not one ("Enable Logic Input", p14), so flags from before the start would hold the FAULT pin and look new (handbook KB-CPP-058); they are reported by GetStartupFaults() and in GetLatchedFaults(). Last, every CFG_CHn and CFG_DPM (bits 14:0) read back must equal what was written. COMER is read only and the datasheet does not say what clears it; a rejected wake write can set it, so it is armed only after the wake: if set then, ENABLE goes low for tDIS and high for tEN and STATUS is read again (2 transfers), kStartAttempts times at most, so that miscounts show in the session; if it still reads set the attempt relies on the read-back, and the session reads every switch-off back. A COMER in a later fault byte repeats the whole procedure, after ENABLE low for tDIS and high again for tEN (both waited in full after the pin write), kStartAttempts times at most. If every attempt fails, cycle VM. 48 transfers when the chip wakes at the first poll, 4 more per extra poll.

The start-up's STATUS reads feed the latch of GetLatchedFaults() like any other, except for UVM before the wake has completed (step 1 reads STATUS precisely to clear the power-on UVM, and the wake polls until it stays clear). The start-up does not empty the latch: a flag latched before it (the UVM of a DeviceReset, say) stays until ClearLatchedFaults().

At the wake timeout: Undervoltage with UVM still set, Timeout with UVM clear. The driver stays uninitialised with every channel off and ENABLE left high, so a retry continues the wake; retry later or report a supply fault, and cycle VM if it persists. On any other failure ENABLE is driven low again.

After it succeeds, later calls return Ok at once with no I/O; after it fails, the next call starts again from the beginning.

Returns
Ok, InvalidArgument (the configuration fails Validate(); no I/O), Bus, Pin, NoDevice, DeviceIdMismatch, WriteMismatch, Undervoltage, Timeout or CommunicationError.

◆ GetLatchedFaults()

template<SpiPort Port>
LatchedFaults max22200::MAX22200< Port >::GetLatchedFaults ( ) const
inlinenoexcept

The clear-on-read flags any read of the driver took from the chip since the last ClearLatchedFaults(), the driver's own reads included (handbook KB-CPP-119). No I/O.

OVT and UVM come from every 32-bit STATUS read: ReadStatus(), the read-back of SetPairMode() and SetFaultMask(), ReadRegister(reg::kStatus) and the start-up's reads. The FAULT flags come from every FAULT read, for the flags it clears: all of them on the MAX22200 (Variant::Max22200), those in which for ClearFaults() on the MAX22200A, and every flag the start-up clears. The summary flags (OVT, UVM, OCP, OLF, HHF, DPM) of every fault byte any access clocks out, the one-transfer ONCH write included, at no cost. Only ClearLatchedFaults() empties it, a restart included; the start-up does not keep the power-on UVM it clears (see EnsureInitialized()). A reply a floating SDO produces (all ones with a 0xFF fault byte) is never taken as flags: a FAULT or STATUS read that clears flags and gets one, or fails, sets lost instead (what the chip held is unknown; a genuine FAULT of 0xFFFFFFFF with a 0xFF fault byte reads the same way). An 8-bit read (ONCH, HOLD) returns neither OVT nor UVM, and the datasheet does not say it clears them; the driver assumes it does not.

Returns
The latched flags.

◆ SetChannelsOn()

template<SpiPort Port>
Result< void > max22200::MAX22200< Port >::SetChannelsOn ( uint8_t  mask,
Verify  verify = Verify::None 
)
noexcept

Switch every channel at once: one 8-bit write of STATUS[31:24] (ONCH). A channel with trigger_pin follows its TRIG pin instead.

2 transfers (command, data), or 1 (the data byte alone, CMD low) when the last access was an ONCH write without Verify::ReadBack and nothing has happened since: no other register access, no failed transfer or pin write, no ENABLE change, no COMER in a fault byte. The data byte's SDO carries STATUS[7:0] (Figure 12), kept in GetLastStatusByte() at no cost. When that byte is 0xFF (no answer: a chip that lost the command in a reset clocks nothing out) the write goes out again with its command, 2 more transfers, so the command byte shows whether the chip was reset.

With Verify::ReadBack, an 8-bit read of ONCH follows (2 more transfers): it must equal mask, and its fault byte must not show COMER. On WriteMismatch the driver's copy takes the value read.

In a pair whose mode is in doubt (see the class), a mask that changes the pair's bits switches both of its channels off; if it set a bit there, the call returns Uncertain after sending the rest of the mask, so every switch-off in it goes out. Nothing is sent when nothing changes and no channel that may still be on is asked off: one a failed write may have switched on, or one whose switch-off no fault byte with COMER clear has vouched for yet.

Parameters
maskBit n switches channel n on. Both bits of a parallel pair must be equal (Table 6).
verifyVerify::None (the default) or Verify::ReadBack.
Returns
Ok, NotInitialized, InvalidArgument (nothing sent), Bus, Pin, DeviceReset, CommunicationError (a new COMER, see the class), and with Verify::ReadBack WriteMismatch. The copy the driver keeps (GetChannelsOn()) changes only when the write went out (on a read-back mismatch it becomes what was read); after Bus the channels it would have changed count as on for the ChannelsActive check until a write succeeds.
