Detailed Description

The SPI port of the MAX22200 driver: the CRTP base, its pin enums, the SpiPort concept and the two-phase register access.

The driver never calls an SDK. It calls hooks on a class you derive from max22200::SpiInterface<Self>:

Hook Contract
bool EnsureInitialized() noexcept Bring the bus and the CMD and ENABLE outputs up on the first call (CMD high, its idle level); true at once afterwards
bool Transfer(const uint8_t* tx, uint8_t* rx, std::size_t len) noexcept One full-duplex transfer of len = 1 or 4 bytes, both buffers given, CSB low throughout and high after
bool GpioSet(CtrlPin pin, GpioSignal signal) noexcept Drive CMD or ENABLE; false when the pin could not be driven
void DelayUs(uint32_t us) noexcept Wait at least us microseconds (tEN and tWU at start-up)

What the chip needs from the bus is below as constexpr values (kSpiMode to kCmdSetupNs, from "SPI Detailed Description" and the SPI rows of the Electrical Characteristics, Figure 1); a port checks its settings against them with static_assert (handbook KB-CPP-123). SDO is open drain: the board needs a pull-up, and its RC sets how fast the bus can run (Electrical Characteristics, note 2). CMD idles high: the driver drives it low only around each data transfer and high again after it, so a GPIO write that returns after the pin changed meets tCMS and tCMH on any MCU.

Control pins and their idle levels (handbook KB-HW-018): the port drives each output to its idle level before it enables the pin's output driver and before the first transfer. CMD idles high (GpioSignal::ACTIVE: the level that selects the Command Register; the driver also drives it high first). ENABLE idles low (GpioSignal::INACTIVE: the chip asleep, every output Hi-Z, until EnsureInitialized() raises it). A board that ties ENABLE high returns true for CtrlPin::Enable without doing anything. FAULT is an input. The port moves raw bytes: it never retries, never interprets the data and never configures the chip. The optional hooks (GpioRead for the FAULT pin, DelayUs is required, Log) are described in max22200.hpp.
