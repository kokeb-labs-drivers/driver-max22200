Variable Documentation

◆ kCmdSetupNs

constexpr uint32_t max22200::kCmdSetupNs = 20
inlineconstexpr

CMD valid before the CSB falling edge that starts a transfer, tCMS. CMD must also stay high through the CSB rising edge that ends a command byte (p26); the hold time tCMH is drawn in Figure 1 with no value, so the driver changes CMD only after Transfer() has returned.

◆ kContinuousWord

constexpr bool max22200::kContinuousWord = false
inlineconstexpr

false: the datasheet sets no limit on idle SCK time between the bytes of one transfer; the chip counts the clocks while CSB is low (a wrong count of a write sets COMER, p34).

◆ kMaxClockHz

constexpr uint32_t max22200::kMaxClockHz = 10'000'000
inlineconstexpr

Highest SCK frequency: tCLK min 100 ns (Electrical Characteristics). "SPI Detailed Description" also says the interface "can operate up to 5MHz" next to the daisy chain, which this driver does not use; the SDO pull-up's RC can set a lower limit (note 2).

◆ kMsbFirst

constexpr bool max22200::kMsbFirst = true
inlineconstexpr

Each byte is clocked most significant bit first (Figure 1). The byte order differs per frame and is the driver's business: a 32-bit write goes LSB byte first, a 32-bit read comes MSB byte first (Figures 10, 11).

◆ kTransferBytes

The transfer lengths the driver asks for, in bytes: 1 (the Command Register, an 8-bit data phase) and 4 (a 32-bit data phase). Nothing else.
